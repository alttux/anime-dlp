# Запуск anime-dlp на Windows из исходного кода

Подробная пошаговая инструкция для тех, кто хочет запустить **и CLI, и GUI**
`anime-dlp` на Windows, собирая программу из исходного кода (а не используя
готовые `.exe` из [Releases](https://github.com/alttux/anime-dlp/releases)).

> Если готовый `.exe` устраивает — самый быстрый путь вообще без этой
> инструкции: скачайте `anime-dlp-windows-x86_64-<версия>.exe` (CLI) или
> `anime-dlp-gui-windows-x86_64-<версия>.exe` (GUI на PyQt6) из
> [Releases](https://github.com/alttux/anime-dlp/releases) и запустите.
> Оба файла автономные, Python ставить не нужно. Эта инструкция нужна, если
> вы хотите запускать код из исходников — для разработки/отладки/своих
> правок, либо чтобы запустить **GTK-версию GUI** (используется на
> Linux/macOS) прямо на Windows через MSYS2 — например, для разработки
> самого GTK-бэкенда.

## Как это устроено на Windows

`anime-dlp` — обычный Python-пакет. Консольная часть (CLI) использует только
чистые Python-библиотеки (`requests`, `rich`, `beautifulsoup4`,
`anime_parsers_ru`) — для неё подходит **любой** Python, в том числе
официальный установщик с [python.org](https://www.python.org/).

Графический интерфейс (`--gui`) на Windows построен на **PyQt6** — у него
есть обычные `pip`-колёса для Windows, никакого системного окружения вроде
MSYS2 не требуется. `anime_dlp/gui/__init__.py` сам выбирает бэкенд по
платформе: PyQt6 на Windows, GTK4 + libadwaita (через `PyGObject`) — на
Linux/macOS; оба реализуют один и тот же набор экранов. `pip install
".[gui]"` на Windows ставит именно `PyQt6` — никаких дополнительных
системных пакетов не нужно, поэтому:

- Для **CLI и/или GUI на PyQt6** — вариант A ниже, он проще и не требует
  MSYS2.
- Для **GTK-версии GUI** конкретно на Windows (нужно очень редко — обычно
  только при разработке самого GTK-бэкенда) — вариант B, требует MSYS2,
  так как готовых pip-колёс GTK4/libadwaita для Windows нет.

## Вариант A — CLI (и, опционально, GUI на PyQt6)

### 1. Установите Python

Скачайте установщик с [python.org/downloads](https://www.python.org/downloads/)
(подойдёт любая версия **3.10 и новее**). При запуске установщика **обязательно
поставьте галочку "Add python.exe to PATH"** на первом экране — без неё
команда `python` не будет находиться в терминале.

Проверьте установку, открыв **PowerShell** (Пуск → введите `PowerShell`) и
выполнив:

```powershell
python --version
```

Должно вывести что-то вроде `Python 3.12.4`.

### 2. Установите Git

Скачайте и установите [Git for Windows](https://git-scm.com/download/win)
(все настройки установщика можно оставить по умолчанию). Проверка:

```powershell
git --version
```

> Без Git можно и обойтись — на странице репозитория GitHub есть кнопка
> **Code → Download ZIP**, которая скачает исходники без установки чего-либо
> дополнительного. Тогда просто распакуйте архив и открывайте PowerShell
> внутри распакованной папки вместо команды `git clone`.

### 3. Скачайте исходный код

```powershell
git clone https://github.com/alttux/anime-dlp.git
cd anime-dlp
```

### 4. Создайте виртуальное окружение и установите зависимости

Виртуальное окружение (venv) — это изолированная копия Python для одного
проекта, чтобы зависимости `anime-dlp` не смешивались с остальными
Python-программами на компьютере.

```powershell
python -m venv .venv
.venv\Scripts\activate
```

После активации в начале строки терминала появится `(.venv)` — значит всё
верно. Дальше ставим зависимости и сам пакет — **без GUI**:

```powershell
pip install -r requirements.txt
pip install .
```

Либо **вместе с GUI на PyQt6** (`pip` сам скачает готовое колесо PyQt6,
никаких системных пакетов ставить не нужно):

```powershell
pip install -r requirements.txt
pip install ".[gui]"
```

### 5. Запустите

```powershell
anime-dlp -d "$HOME\Videos\Anime"
```

Если ставили `".[gui]"` — можно запустить и графический интерфейс:

```powershell
anime-dlp --gui
```

Если PowerShell не находит команду `anime-dlp` — убедитесь, что venv
активирован (шаг 4, `(.venv)` в начале строки; если открыли терминал заново,
команду `.venv\Scripts\activate` нужно повторить).

### 6. (Опционально) ffmpeg — для серий без прямой ссылки

Часть серий Kodik отдаёт только потоковой ссылкой (HLS), для них нужен
`ffmpeg` в `PATH`:

```powershell
winget install ffmpeg
```

Если `winget` недоступен — скачайте сборку с
[ffmpeg.org/download.html](https://ffmpeg.org/download.html) (раздел
Windows → builds from gyan.dev), распакуйте и добавьте папку `bin` внутри
архива в переменную окружения `PATH`. Без `ffmpeg` скачаются только серии,
которые Kodik отдаёт напрямую (таких большинство) — программа не упадёт,
просто конкретная серия завершится ошибкой с понятным сообщением.

Дальше можно сразу перейти к разделу
[«Аргументы командной строки»](#аргументы-командной-строки) — для CLI
на этом всё.

## Вариант B — GTK-версия GUI через MSYS2

> Обычно не нужен: GUI на Windows — это PyQt6 (вариант A выше, обычный
> `pip`, без MSYS2). Этот вариант нужен только чтобы запустить именно
> **GTK4/libadwaita-версию** интерфейса (ту же, что используется на
> Linux/macOS) прямо на Windows — например, при разработке GTK-бэкенда.

### 1. Установите MSYS2

Скачайте установщик с [msys2.org](https://www.msys2.org/) (кнопка со
ссылкой на `.exe`, актуальная версия) и запустите его:

1. Оставьте путь установки по умолчанию — `C:\msys64`.
2. Пройдите мастер установки до конца, оставив галочку **"Run MSYS2 now"**
   на последнем экране — откроется терминал MSYS2.

### 2. Обновите MSYS2

В открывшемся терминале (это базовый терминал **MSYS2 MSYS** — он нужен
только для этого шага) выполните:

```bash
pacman -Syu
```

Пакетный менеджер обновит системные компоненты и, скорее всего, попросит
**закрыть терминал** (`Y` на вопрос, затем окно закроется само — это
нормально, не ошибка). Откройте **заново** из меню Пуск пункт
**"MSYS2 MSYS"** и выполните ту же команду ещё раз, чтобы добить обновление
до конца:

```bash
pacman -Syu
```

Повторяйте, пока команда не отработает без предложений что-то обновить.

### 3. Откройте нужный терминал — MSYS2 MinGW64

Это важный момент: у MSYS2 несколько разных терминалов в меню Пуск
(`MSYS2 MSYS`, `MSYS2 MINGW32`, `MSYS2 MINGW64`, `MSYS2 UCRT64`...) — они
дают разные окружения. Всё, что установится дальше, нужно ставить и
запускать именно из **`MSYS2 MinGW64`** — найдите этот пункт в меню Пуск и
откройте его. Дальнейшие команды выполняются в нём.

### 4. Установите GTK4, libadwaita, Python и ffmpeg

```bash
pacman -S mingw-w64-x86_64-python \
          mingw-w64-x86_64-python-pip \
          mingw-w64-x86_64-python-gobject \
          mingw-w64-x86_64-gtk4 \
          mingw-w64-x86_64-libadwaita \
          mingw-w64-x86_64-gsettings-desktop-schemas \
          mingw-w64-x86_64-adwaita-icon-theme \
          mingw-w64-x86_64-hicolor-icon-theme \
          mingw-w64-x86_64-ffmpeg
```

На вопросы вида `Proceed with installation? [Y/n]` отвечайте Enter
(по умолчанию — да). Загрузка займёт какое-то время (GTK4 — тяжёлый пакет,
скачается несколько сотен мегабайт).

Проверка, что Python внутри MSYS2 — это именно тот, mingw64-версии:

```bash
which python
# должно быть: /mingw64/bin/python
python --version
```

Если `which python` показывает что-то из `/usr/bin` — значит вы всё-таки в
терминале `MSYS2 MSYS`, а не `MSYS2 MinGW64`. Закройте терминал и откройте
правильный (шаг 3).

### 5. Скачайте исходный код anime-dlp

Git в MSYS2 MinGW64 обычно уже есть (входит в базовую поставку). Если
команда `git` не находится — поставьте её: `pacman -S git`.

```bash
git clone https://github.com/alttux/anime-dlp.git
cd anime-dlp
```

> Если репозиторий уже был скачан в варианте A (обычным Git for Windows) —
> открывать заново не обязательно, просто перейдите в ту же папку из
> терминала MSYS2. Диски Windows видны в MSYS2 как `/c/...`, например
> `cd /c/Users/ИмяПользователя/anime-dlp`.

### 6. Установите anime-dlp

`PyGObject` уже установлен через `pacman` на предыдущем шаге и виден этому
Python — ставить пакет `anime-dlp` с extras `[gui]` не нужно (тот extras
на Windows тянет `PyQt6`, а не `PyGObject`, см. `pyproject.toml`):

```bash
python -m pip install --no-build-isolation .
```

Если pip пожалуется на "externally-managed-environment" — добавьте флаг
`--break-system-packages`:

```bash
python -m pip install --no-build-isolation --break-system-packages .
```

### 7. Запустите GTK-версию GUI

По умолчанию `anime-dlp --gui` на Windows запускает **PyQt6**-версию — для
GTK-версии, установленной в этом варианте, задайте переменную окружения
`ANIME_DLP_GUI_BACKEND=gtk`. Из того же терминала **MSYS2 MinGW64**:

```bash
ANIME_DLP_GUI_BACKEND=gtk anime-dlp --gui
```

Откроется окно программы (на GTK4/libadwaita). Консольная версия работает
точно так же и без этой переменной:

```bash
anime-dlp -d /c/Users/ИмяПользователя/Videos/Anime
```

**Важно:** и CLI, и GUI после установки в MSYS2 запускаются **только из
терминала MSYS2 MinGW64** (или через ярлык из следующего раздела) — из
обычного PowerShell/cmd.exe команда `anime-dlp` не найдётся, если только вы
не добавите `C:\msys64\mingw64\bin` в системный `PATH` вручную.

## Аргументы командной строки

| Флаг                | Описание                                                                 |
|----------------------|---------------------------------------------------------------------------|
| `-d`, `--dir`        | Директория для скачивания (по умолчанию — `%APPDATA%`-профиль, см. ниже) |
| `--logging`          | Сохранять весь вывод консоли в файл `anime-dlp.log` внутри директории загрузки |
| `--gui`              | Запустить графический интерфейс (PyQt6; `ANIME_DLP_GUI_BACKEND=gtk` — версия на GTK4, вариант B) |
| `-h`, `--help`       | Показать справку по аргументам                                          |

## Куда сохраняются файлы и токен

При запуске **из исходников** (`pip install .`, оба варианта A и B) пакет
копируется внутрь `site-packages` того окружения, куда его ставили — и
именно там, а не в папке проекта, по умолчанию создаются папка `downloads/`
и файл токена Kodik `.kodik_token`. Путь неудобный и малозаметный, поэтому
**всегда указывайте `-d`** явно:

```powershell
anime-dlp -d "C:\Users\ИмяПользователя\Videos\Anime"
```

Если всё же нужно найти файлы, сохранённые без `-d`, вот точные пути:

- **Вариант A** (обычный Python + `.venv`):
  `<папка проекта>\.venv\Lib\site-packages\anime_dlp\downloads`
- **Вариант B** (MSYS2, без отдельного `.venv`):
  `C:\msys64\mingw64\lib\python3.*\site-packages\anime_dlp\downloads`
  (звёздочка — версия Python, например `python3.12`)

(Это поведение относится только к запуску **из исходников**. У готового
`.exe` из Releases — другое: он использует `%APPDATA%\anime-dlp` для токена
и `~\Downloads` для загрузок по умолчанию, см. `config.py` → `IS_FROZEN`.)

## Быстрый запуск без терминала (ярлык)

Чтобы не открывать каждый раз терминал MSYS2 вручную, создайте `.bat`-файл
на рабочем столе, например `anime-dlp-gui.bat`, со следующим содержимым
(поправьте путь к проекту под свой):

```bat
@echo off
C:\msys64\usr\bin\bash.exe -lc "cd /c/Users/ИмяПользователя/anime-dlp && ANIME_DLP_GUI_BACKEND=gtk anime-dlp --gui"
```

Двойной клик по этому файлу откроет GTK-версию GUI напрямую, без
необходимости разбираться с терминалами MSYS2 каждый раз.

Для варианта A (обычный Python + `.venv`, GUI на PyQt6) можно сделать
аналогичный `.bat`:

```bat
@echo off
call "C:\Users\ИмяПользователя\anime-dlp\.venv\Scripts\activate.bat"
anime-dlp -d "%USERPROFILE%\Videos\Anime"
pause
```

## Обновление

Чтобы обновить anime-dlp до последней версии из репозитория:

```bash
cd anime-dlp
git pull
python -m pip install --no-build-isolation .   # для варианта B (GTK)
# либо для варианта A (в активированном .venv):
# pip install ".[gui]"   # с PyQt6-версией GUI, или просто `pip install .` без GUI
```

## Решение проблем

**`'anime-dlp' is not recognized as an internal or external command`**
Виртуальное окружение/MSYS2-терминал не активированы в текущем сеансе
терминала. Вариант A: выполните `.venv\Scripts\activate` в PowerShell из
папки проекта. Вариант B: убедитесь, что открыт именно терминал
**MSYS2 MinGW64** (не MSYS2 MSYS/MINGW32).

**`ModuleNotFoundError: No module named 'PyQt6'` при запуске `--gui` (вариант A)**
GUI-зависимость не установлена в этот `.venv` — выполните
`pip install ".[gui]"` в активированном окружении (шаг 4).

**`ModuleNotFoundError: No module named 'gi'` при `ANIME_DLP_GUI_BACKEND=gtk anime-dlp --gui` (вариант B)**
GTK-зависимости не установлены в тот Python, из которого запускается
программа. Убедитесь, что вы в терминале MSYS2 MinGW64 и что шаг 6
(`pip install .`) выполнялся именно там, а не в обычном PowerShell.

**Окно GUI открывается, но иконки — пустые квадраты/крестики**
Не хватает темы иконок. Проверьте, что при установке пакетов (шаг 4) не
пропущены `mingw-w64-x86_64-adwaita-icon-theme` и
`mingw-w64-x86_64-hicolor-icon-theme`.

**`pacman` пишет `error: failed to commit transaction (conflicting files)`**
Обычно помогает повторный запуск `pacman -Syu`, а если не помогает —
`pacman -Syuu` (форсированное обновление до последней версии пакетов).

**Windows SmartScreen блокирует запуск `.exe` из Releases**
Это стандартное предупреждение Windows для исполняемых файлов без цифровой
подписи (подписание сертификатом стоит денег и не делается для
open-source-утилит). Нажмите **"Подробнее" → "Выполнить в любом случае"**.
Если не доверяете — соберите `.exe` сами:
- CLI: `pip install pyinstaller && pyinstaller --onefile --name anime-dlp
  packaging/pyinstaller_entry.py`, после `pip install .`.
- GUI (PyQt6): `pip install ".[gui]" pyinstaller && pyinstaller --onefile
  --windowed --icon packaging/windows/AnimeDlp.ico
  packaging/windows_gui_entry.py`.

Либо запускайте из исходников по этой инструкции.

**Ошибка про ffmpeg при скачивании конкретной серии**
Значит эта серия доступна только через HLS-поток — установите `ffmpeg`:
вариант A → раздел [ffmpeg](#6-опционально-ffmpeg--для-серий-без-прямой-ссылки),
вариант B → он уже ставится на шаге 4 (`mingw-w64-x86_64-ffmpeg`).

**Скачивание работает, но очень медленно**
Проверьте, не блокирует ли антивирус/файрвол исходящие соединения от
`anime-dlp.exe`/`python.exe` — при первом запуске Windows Defender Firewall
может спросить разрешение, разрешите доступ к сети.
